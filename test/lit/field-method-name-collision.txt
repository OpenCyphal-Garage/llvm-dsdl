# Regression: a DSDL field named the same as a generated method (`serialize` / `deserialize`) is
# spec-valid (not a language keyword, so the frontend accepts it) but collides with the type's methods
# in Go (a struct field and method cannot share a name -> compile error) and Python (a dataclass
# attribute shadows the method, so `self.serialize()` tries to call an int at runtime). Rust (fields and
# inherent methods occupy separate namespaces) and C/C++/TypeScript (free functions, not members) are
# unaffected. The Go/Python field allocators now reserve the generated method names, so such a field is
# escaped (`Serialize_2` / `serialize_2`) while the method keeps its name. See the composite-reference
# read-as-review.
